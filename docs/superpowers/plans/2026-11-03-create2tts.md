# Create2TTS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Local Thai/English TTS worker with voice cloning, effects, web GUI and MCP server, started on demand.

**Architecture:** One FastAPI worker process owns the models and serves REST + the built GUI; a torch-free MCP stdio server and CLI talk to it over HTTP and spawn it when needed. Pure modules (text, effects, audio/voices) are unit-tested; the service is tested with a fake engine.

**Tech Stack:** Python 3.12 (uv), f5-tts 1.1.22, torch (MPS), transformers Whisper, pedalboard, pythainlp, FastAPI, mcp (FastMCP), httpx; Vite + React 18 + TypeScript.

**Spec:** `docs/superpowers/specs/2026-11-03-create2tts-design.md`

## Global Constraints

- Python `>=3.12,<3.13`; run everything with `uv run`; tests `uv run pytest -q`.
- Shared types are fixed in `src/create2tts/models.py` and `src/create2tts/config.py` — import them, do not redefine or edit them (ask the orchestrator if a field is missing).
- Comments in English, only for what code cannot say, one line, ~10 words max; no docstring paragraphs.
- Never import `torch`, `f5_tts`, `transformers` or `pedalboard` from `client.py`, `mcp_server.py`, `cli.py` (except lazily inside `serve`).
- Tests must not download models; real-model tests carry `@pytest.mark.model` (skipped by default).
- Tests set `CREATE2TTS_DATA` to a tmp dir (fixture) so `data/` is never touched.

## Review Focus

- Upload of a browser recording (webm/ogg) as a reference clip → decoded via ffmpeg, not rejected (Task 3 test with an ogg made by ffmpeg).
- Very long text (5,000 Thai chars, no spaces) → split into ≤ `max_chars` segments, no infinite loop (Task 1 test).
- `../` or absolute names in `/api/outputs/{file}` and voice ids → 404, never read outside `data/` (Task 3, Task 8 tests).
- Two MCP sessions calling at once with no worker → exactly one worker spawned (Task 4 test: lock prevents a second spawn).
- Worker idle while a GUI tab is open → models unloaded but process stays (Task 8 lifecycle test).
